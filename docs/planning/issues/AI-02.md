## Что сделать
Поднять в Google Colab сервис рекомендаций: готовая открытая LLM через Ollama (по умолчанию Qwen3 8B) + RAG по базе знаний из проверенных источников. Сравнить модели и открыть сервис для backend по публичному адресу.

## Детали / спецификация
- Ноутбук — `docs/ai/fitquest_rag_colab.ipynb`, описание и контракт — `docs/ai/README.md`.
- База знаний: ВОЗ 2020 (ru/en), бюллетень ВОЗ «Физическая активность», ACSM Position Stand 2026, HHS 2018, UK CMO 2019 — полные тексты скачиваются при запуске и в git не кладутся; карточки-пересказы ACSM 2009, Garber 2011, Tanaka 2001, Paluch 2022, Riebe 2015 и правил FitQuest. Таблица источников с лицензиями — в `docs/ai/README.md`.
- Фрагменты ~900 символов с перекрытием, индекс FAISS; эмбеддинги `multilingual-e5-large` или `bge-m3` — выбор по hit@4 и MRR на 12 размеченных вопросах.
- LLM-кандидаты: `qwen3:8b`, `qwen3:4b`, `gemma3:12b`, `gemma3:4b`, `llama3.1:8b`, `qwen2.5:7b` (все помещаются в T4). 8 сценариев: новичок, регулярные силовые, перерыв, тревожные симптомы, пожилой, мало шагов, высокий пульс, вопрос про таблетки. Метрики: валидный JSON, русский язык, ссылки на источники, интенсивность, безопасность (прибавка ≤ 10%, совет обратиться к врачу, без лекарств), время ответа.
- Ответ модели — JSON по схеме (`format` в Ollama), у Qwen3 `think: false`; после модели — проверки в коде (перерыв ≥ 5 дней или симптомы → `light`).
- FastAPI: `POST /v1/recommend`, `POST /v1/ask`, `GET /health`; заголовок `X-AI-Token` (секрет Colab `FITQUEST_AI_TOKEN`). Публичный адрес — туннель ngrok (секрет `NGROK_AUTHTOKEN`) или cloudflared.

## Критерии готовности
- [ ] Ноутбук выполняется сверху вниз на T4, индекс строится и при недоступном сайте источника (на карточках)
- [ ] Таблицы hit@4/MRR и сравнения LLM с обоснованием выбора — в `docs/ai/README.md`
- [ ] `curl` на публичный адрес с токеном возвращает рекомендацию, без токена — `401`
- [ ] Токены только в секретах Colab, не в ноутбуке
